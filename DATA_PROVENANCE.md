# Data Provenance

## Formal Data Scope

This project treats only CNINFO public announcements as formal source data.

Formal metadata records must satisfy all of the following:
- `announcement_url` points to `cninfo.com.cn`
- `pdf_url`, when present, points to `static.cninfo.com.cn`
- `notes` or `data_source` must not contain sample, synthetic, generated, random, 示例, 合成, 虚构, or 随机 markers
- placeholder values such as `未知公司` and `未知转债` are not allowed in formal metadata

## Formal Files

- `data/metadata/metadata.csv`: formal CNINFO announcement metadata
- `data/bonds/bond_list.csv`: convertible bond reference list used for matching and review
- `outputs/extract_results/structured_data_standardized.json`: standardized extraction records derived from parsed announcements
- `outputs/extract_results/records_validated.csv`: records after schema validation
- `outputs/event_chain/event_chains.csv`: event chains generated by the formal process module
- `outputs/indicators/quantitative_indicators.csv`: metrics generated from formal event chains

## Non-Formal Review Files

- `outputs/review/metadata_review_queue.csv`: optional manual review queue generated from parsed Markdown; it is not formal metadata until manually checked against CNINFO.
- `data/metadata/metadata_quality_issue_backup.csv`: backup of records with known quality issues; it is retained for audit and is not used as the formal metadata source.

## Guardrails

- `src/crawl/real_data_guard.py` validates metadata provenance before formal metadata is saved or rewritten.
- `generate_metadata.py` no longer writes `data/metadata/metadata.csv`; it only creates a manual review queue.
- Demo/test records must be marked with `data_source=sample` and are rejected by formal metadata saving unless explicitly allowed for tests.
